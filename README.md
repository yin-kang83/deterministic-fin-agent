# 确定性业财智能体 · 参考实现（论文复现包）

> DOI: [10.5281/zenodo.24295146](https://doi.org/10.5281/zenodo.24295146)


> 本仓是**论文的复现包**，不是产品：只放**最小可跑、每个断言都能失败**的机制实现。
> 产品实现为专有代码，不随本仓分发；本仓可独立运行。

## 证明什么

| 方向 | 内容 |
|---|---|
| 本仓 | **机制可行**：哈希链能验篡改、优先级能解冲突、Decimal 不失真、缺事实即拒绝 |
| 产品实现（私有） | 规模可用（不随本仓提供） |

论文/报告引用时请分开表述"机制"与"规模"，不要把本仓的最小实现当作完整系统。

## 目录

```text
src/       最小实现（audit_chain.py 哈希链+Decimal / card_router.py 多卡路由+优先级 /
           boundary.py 控制位边界 / state_machine.py 状态机 / recurrence.py 差分方程 /
           actuarial.py 精算形式 / stable_forms.py 形式选择规则）
cases/     构造案例（输入文本 + 事实集 + 期望输出 + 依据），全部人工可复核
tests/     断言（每条能力都必须有能推翻它的用例）
scripts/   演示与造数脚本
```

## 数据纪律

**不复用任何业务数据集**（年报 PDF、题库、题库覆盖图里的东西一律不进本仓）。

每个案例是一个独立 JSON，含「来源」字段：

```json
{
  "id": "CASE-001",
  "来源": "构造（合成数据，非真实业务数据）",
  "原始文本": "…",
  "期望事实集": {"…": "…"},
  "期望结果": {"status": "…"},
  "依据": "税法条款 / 准则段落 / 或「本案例为构造，仅用于验证机制」"
}
```

「来源」写"构造"就说明它不是实证，不得当作实证数据引用。

## 已实现的四项能力与其断言

| 能力 | 断言（能推翻它的是什么） |
|---|---|
| Decimal 精确 | `0.1 + 0.2 == 0.3`；`float` 构造金额抛 `TypeError` |
| 哈希链可验 | 篡改第 2 块 → `verify()` 返回 `(False, 1, 原因)` |
| 优先级解冲突 | 两张卡同时命中 → 取 priority 小者，且冲突被记录 |
| fail-closed | 无卡适用 → 拒绝，不猜 |

## 运行

```bash
# 本仓自检（纯标准库，无需安装依赖）
python -m tests.test_integration     # 跨模块自检：6 项
python -m tests.test_vendored        # 与产品实现的一致性检查（产品仓不存在时自动跳过并明示）
```

## 明确不做

- 不做 LLM 抽取（本仓不接模型，事实集由案例给出）
- 不声称「满足司法证据保全」（需可信时间戳/第三方签名；本仓只保证链内一致）
- 不声称「零幻觉」（无对照实验即不可宣称）
- 不提供法律、税务或投资意见
