# 确定性业财智能体 · 参考实现

> 这个仓库是**论文的复现包**，不是产品。
> 产品在 `E:\康正财务智能体`（142 个引擎 / 525 项自检），规模在那里；
> 这里只放**最小可跑、每个断言都能失败**的机制实现。

## 两个仓库的分工

| 仓库 | 证明什么 |
|---|---|
| **本仓** | **机制可行**：哈希链能验篡改、优先级能解冲突、Decimal 不失真、缺事实即拒绝 |
| 产品仓 | **规模可用**：142 引擎 / 525 项自检 / 覆盖率 94.2% |

**论文里必须两个都引。只引本仓，会被问「就这么点」；只引产品仓，会被问「机制在哪」。**

## 目录

```
src/       最小实现（audit_chain.py 哈希链+Decimal / card_router.py 多卡路由+优先级）
cases/     干净案例（输入文本 + 事实集 + 期望输出 + 依据），全部人工可复核
tests/     断言（每条能力都必须有能推翻它的用例）
paper/     架构稿与其评审表
```

## 数据纪律（「干净数据」的含义）

**不复用任何业务数据集**（年报 PDF、题库、题库覆盖图里的东西一律不进本仓）。

每个案例是一个独立 JSON：

```json
{
  "id": "CASE-001",
  "来源": "构造（非真实客户数据）",
  "原始文本": "…",
  "期望事实集": {"…": "…"},
  "期望结果": {"status": "…"},
  "依据": "税法条款 / 准则段落 / 或「本案例为构造，仅用于验证机制」",
  "对应断言": "tests/test_cases.py::test_case_001"
}
```

**「来源」字段是硬要求**：写了「构造」就说明它不是实证；不许把构造数据当实证引用。

## 已实现的四项能力与其断言

| 能力 | 断言（能推翻它的是什么） |
|---|---|
| Decimal 精确 | `0.1 + 0.2 == 0.3`；`float` 构造金额抛 `TypeError` |
| 哈希链可验 | 篡改第 2 块 → `verify()` 返回 `(False, 1, 原因)` |
| 优先级解冲突 | 两张卡同时命中 → 取 priority 小者，且**冲突被记录** |
| fail-closed | 无卡适用 → 拒绝，不猜 |

## 明确不做

- 不做 LLM 抽取（本仓不接模型，事实集由案例给出）——**那是产品仓的事**
- 不声称「满足司法证据保全」（需可信时间戳/第三方签名；本仓只保证链内一致）
- 不声称「零幻觉」（无对照实验即不可宣称）
